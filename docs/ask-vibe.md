# ask-vibe

## 它做什么

告诉你现在在流程的哪一步，并给出下一条要敲的命令。命令是一个完整的文本块，路径和要附加的话都已经填好，你复制粘贴就行。

它先看仓库状态来判断位置：有没有做过两个 setup、有没有没做完的票、有没有还没拆票的规格、当前分支有没有合并、有没有 ROADMAP、wayfinder 地图走完没有。然后按三层流程（项目层、Milestone 层、票层）给你下一步，并说明要不要先清空上下文、做完后看什么。

## 什么时候用

- 开新窗口、隔天继续、忘了下一步做什么的时候。
- 每做完一步不确定接下来该敲什么的时候。
- 想知道这次改动要不要切回完整版 SOP 的时候。

## 常见问题

**它为什么不直接帮我运行下一步？** 两个原因。技术上，`to-spec`、`to-tickets`、`implement`、`wayfinder`、`grill-with-docs` 都只能由你手动敲，Agent 调不了。流程上，每一步之间本来就要你确认上一步的产出，很多时候还要先清空上下文。

**它会不会判断错位置？** 它按固定顺序检查，第一个符合的就是你的位置，并会说出依据。依据不对就告诉它，比如"我其实已经合并了"。wayfinder 的决策票（`.scratch/plan-*/`）不会被当成开发票。

**它怎么知道哪个 Milestone 做完了？** 看 `docs/ROADMAP.md` 里的勾选框。每个 Milestone 收尾合并时，它给的命令里会包含"把这一项打勾并提交"。分支、规格目录和票都用同一个 Milestone 代号（比如 `m0-a`），它靠这个把三者对上。

**出现第二个同类实例时它会提醒吗？** 会。它会让你在 grill、to-spec、to-tickets 三步各多加一句，先把契约抽出来，再一个实例一张票。

**小任务也要用它吗？** 不用。说不清就先 `/grill-with-docs` 聊几句，然后直接 `/implement`。

## 怎样算在正常工作

- 它给出的位置和你的实际进度一致，并列出了判断依据。
- 它给的命令能原样粘贴运行，路径都是真实存在的。
- 需要清空上下文的地方，它会提醒你先 `/clear`。
